# Content Safety

**Runs on incoming messages**

Stops abusive messages from reaching the assistant, and hides slurs in messages that are otherwise fine.

## What happens

**⊖ Blocks — sends set reply** — If the message is rated as toxic, it never reaches the AI assistant. The user gets a reply asking them to rephrase.

**↻ Fixes & passes on** — If the message only contains a listed slur and is not rated toxic overall, the slur is hidden and the message continues as normal.

## Example

| | |
| --- | --- |
| **User** | `You are a worthless idiot, get lost` |
| **User gets** | `Please rephrase the query without unsafe content.` |

The assistant never sees the message.

:::info

The reply is automatically translated by AI to match the language and script the user wrote in — Hindi in Devanagari, Hinglish in Latin letters, English unchanged. You can write your own reply instead of the default.

:::

:::info

Tested on English, Hindi and Hinglish. Other languages are not tested.

:::

## Without this guardrail

:::danger

The abusive word reaches the assistant, and may appear again in the reply. **Risk:** abusive language is not stopped, which hurts trust and looks bad for your organisation.

:::

## How well it works

<MetricsHeadline validator="content_safety" />

Tested on real-style messages in English, Hindi and Hinglish.


## Known limitations

:::warning

- **More false alarms than before.** About 1 in 5 flagged messages is actually clean, mostly everyday Hinglish chat and some political Hindi. Part of this is label noise in the test set.
- **A toxic message is blocked as a whole**, not word by word, so the user always gets the rephrase reply.
- **Indirect insults are missed**, especially Hindi political ones with no abusive words.
- **It is slower** than a word list: an AI model runs on every message (about 7 ms).

:::
