# Privacy Protection

**Runs on incoming messages**

Finds personal details in what users send your assistant, and removes them before the message is answered or saved.

:::tip

Enabling this guard helps your organisation stay compliant with India's DPDP Act and GDPR.

:::

## What happens

**↻ Fixes & passes on** — The message continues as normal, with personal details hidden. The user is not interrupted.

## Example

| | |
| --- | --- |
| **User** | `Mera naam Rahul Sharma hai, number 98765 43210 hai aur PAN ABCDE1234F hai.` |
| **Assistant sees** | `Mera naam XXXXX XXXXX hai, number XXXXX XXXXX hai aur PAN XXXXXXXXXX hai.` |

The real numbers are never saved or shown anywhere.

## Without this guardrail

:::danger

Personal details get saved and can be shown again in the chat, exactly as the user typed them. **Risk:** personal data can leak, and users stop trusting your service.

:::

## Settings

Validator: `pii_remover`.

| Setting | Values | What it does |
| --- | --- | --- |
| `entity_types` | list (default: all pattern-based types) | What to mask, e.g. `PHONE_NUMBER`, `EMAIL_ADDRESS`, `CREDIT_CARD`, `IN_AADHAAR`, `IN_PAN`, `IN_PASSPORT`, `IN_VOTER`. `PERSON`, `LOCATION` and `NRP` are opt-in. |

:::info

The scores below were measured with all types switched on, including names and locations. With the default list, names, places and nationalities are not masked, so real recall is lower.

:::

## How well it works

<MetricsHeadline validator="pii_remover" />

Tested on real-style messages in English, Hindi, Hinglish, Kannada, Marathi and Telugu, with every personal-detail type switched on.


## Known limitations

:::warning

- **About 1 in 4 personal details is still left in the text.** Names are the hardest (about 7 in 10 fully masked); some names keep a fragment.
- **Nationalities and religions (NRP) are almost never masked**, because the Indian-language name model has no label for them.
- **Indian medical registration numbers are not recognised.**
- **Scores are similar across all six languages**, so no language is clearly weaker.
- **Aadhaar and IBAN scores are understated:** most of the synthetic numbers in the test set are invalid, so they are not recognised. Valid Aadhaar numbers were all caught.

:::
